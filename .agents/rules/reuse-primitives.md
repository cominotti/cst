# Reuse before you write

A concept more than one module needs lives once, in `cst_core`. Before you write
code that runs a command, reads or writes a file, creates a folder, takes a lock,
logs to the journal, reads the clock, tells the host from a toolbox, parses a
size, a duration, a CPU list, a KEY=VALUE settings file, JSON or TOML, reads a
regex group, names an exit status or a word several modules share, or renders
a systemd unit, find the primitive below and import it from the module named.

**If it lacks an option you need, add the option to the primitive, with its
tests (`tests/test_cst_core.py`, `tests/test_cst_core_shared.py`), in the same
change. Do not copy it into your module.** A copy drifts: the next fix lands in
one place only.

## Need -> primitive

| Need | Use | Notes |
|---|---|---|
| Run a command | `CommandRunnerPort` (`cst_core.ports`), `SubprocessCommandRunner` (`cst_core.adapters.runner`) | `CommandResult`, `CommandFailed` in `cst_core.ports`. Tests inject a fake through the port. Every option is off by default and a call names what it needs: `timeout`, `input_text`, `env`/`unset`/`base_env`, `cwd`, `locale_c` (a command whose answers are parsed: not an `LC_ALL` literal), `new_session`, `on_host` (`flatpak-spawn --host` inside a container), `stdin`, `output`, `decode_errors` (a `DecodeErrors`; by default bytes that are not UTF-8 become U+FFFD; `"strict"` raises instead: docker-volumes-nocow asks for it, for systemctl's answer, and bulk, for btrfs-snapshot's output; `"surrogateescape"` keeps them as lone surrogates, which become the same bytes again on a surrogateescape write or in an argv: btrfs-snapshot-runtime asks for it, as bash passed them on), `nice`, `pass_fds` (open descriptors the command keeps: a lock handed on), `output=OutputMode.STDOUT_SHOW_STDERR` (stdout captured, stderr left on ours, as a shell's `$(cmd)`), `on_line` (each line of the captured stdout as soon as the command writes it, for a caller that passes lines on live; with `output` merge, stdout or stdout-show-stderr, and timeout(1) in argv instead of `timeout`). `output` takes an `OutputMode` member and `fault` is a `CommandFault` member (`missing`, `unstartable`, `timeout`; both StrEnums in `cst_core.ports`); `stdin` is `"devnull"` (the default) or `"inherit"` (`StdinMode`). `c_locale(env)` gives an environment with `LC_ALL=C` for a command run outside the runner; `on_host_argv(argv, settings)` the `flatpak-spawn --host` command line of one, for a command a program execs or hands on itself (toolchains runs itself on the host with it, cpu-setup its `cpu-watch`). A command that is missing, cannot start or times out comes back with `fault` and `cause` set: a module keeps its own message from them (a 2-line binding), never its own `subprocess.run`; `r.failure(what)` (`CommandResult`) is the one error text of a failed step, `WHAT failed: STDERR` or `WHAT failed: exit N` when it wrote nothing (iocost's and scrub-limit's steps); `r.raise_cause()` gives `r` back or raises that cause, for a caller that lets it propagate as `subprocess.run` raised it (bulk and docker-volumes-nocow; docker-gc, vm, cpu, toolchains, bluetooth and snapshot still write its two lines out). Outside it on purpose: the children a program reads or watches while they run (`subprocess.Popen`: docker events, restic, `pactl subscribe`, the cpu watch, the stall monitor's alert, bulk's copy; each counted in `PRIMITIVE_BUDGETS`) and the dispatcher's foreground run. The restorecon call of `cst_core.adapters.files` (write_atomic's relabel) runs through it too. With `on_host` inside a container, `env` values go on `flatpak-spawn`'s command line: never a secret there. |
| Host or toolbox, run on the host | `HostExecutionContext` (`cst_core.adapters.runner`), `ExecutionContextPort`, `ContainerProbePort` | The one detection in Python: the dispatcher, doctor's `Host` and toolchains ask it (a module's test override, such as `CST_DOCTOR_CONTAINER`, stays in front of it). Root commands refuse inside a toolbox ([docs/architecture.md](../../docs/architecture.md#toolbox-vs-host)). A managed command line (`run_managed_cli`, `enforce_host_root` in `cst_core.adapters.runtime`) refuses there and otherwise runs itself again through `sudo -- env CST_PROG=... CST_LC_CTYPE=... SYSTEM_PYTHON -I -B ENTRY ARGS...`: root never runs the caller's interpreter. |

## The gates that catch a copy

- `tests/test_duplication.py`: clones, and the same name defined in several
  files (Python top-level names and shell functions).
- `tests/test_architecture.py`: no I/O in `domain` or `application`; and
  `PRIMITIVE_OWNERS` / `PRIMITIVE_LITERALS`, which name the owner of each
  primitive (running a command, replacing or syncing a file, temporary files,
  locks, the NOCOW ioctl, parsing JSON or TOML: `json.load(s)` and
  `tomllib.load(s)` have no budget, so a call in production code outside
  `cst_core.domain.shapes` fails) and of the literals that betray a copy of one
  (`/run/.containerenv`, `/.dockerenv`, `flatpak-spawn`, `qemu:///system`,
  `LC_ALL`, `restorecon`, `systemd-escape`). A call or a literal anywhere
  else counts against its package's budget (`PRIMITIVE_BUDGETS`,
  `LITERAL_BUDGETS`), which it may not go above: a new copy fails. Every public
  name of cst_core's shared layers must have a user outside its file
  (`CORE_NAMES_WITHOUT_USER` lists today's exceptions).
- `tests/test_magic_values.py`: a word of a cst_core StrEnum (`OwnedState`,
  `Urgency`, ...) compared as a plain string, and a unit number written out
  (3600, 86400, 604800, 124, 126, 127, 137) where cst_core has its name
  ([magic-values](magic-values.md)).
