# Reuse before you write

A concept more than one module needs lives once, in `cst_core`. Before you write
code that runs a command, reads or writes a file, creates a folder, takes a lock,
logs to the journal, reads the clock, tells the host from a toolbox, parses a
size, a duration, a CPU list, a KEY=VALUE settings file, JSON or TOML, reads a
regex group, names an exit status or a word several modules share, or renders
a systemd unit, find the primitive below and import it from the module named.

**If it lacks an option you need, add the option to the primitive, with its
tests (`tests/test_cst_core.py`, `tests/test_cst_core_shared.py`), in the same
change. Do not copy it into your module.** A copy drifts: the next fix lands in
one place only.

## Need -> primitive

| Need | Use | Notes |
|---|---|---|
| Run a command | `CommandRunnerPort` (`cst_core.ports`), `SubprocessCommandRunner` (`cst_core.adapters.runner`) | `CommandResult`, `CommandFailed` in `cst_core.ports`. Tests inject a fake through the port. Every option is off by default and a call names what it needs: `timeout`, `input_text`, `env`/`unset`/`base_env`, `cwd`, `locale_c` (a command whose answers are parsed: not an `LC_ALL` literal), `new_session`, `on_host` (`flatpak-spawn --host` inside a container), `stdin`, `output`, `decode_errors` (a `DecodeErrors`; by default bytes that are not UTF-8 become U+FFFD; `"strict"` raises instead: docker-volumes-nocow asks for it, for systemctl's answer, and bulk, for the commands it ran with `text=True`; `"surrogateescape"` keeps them as lone surrogates, which become the same bytes again on a surrogateescape write or in an argv: btrfs-snapshot-runtime asks for it, as bash passed them on), `nice`, `pass_fds` (open descriptors the command keeps: a lock handed on), `output=OutputMode.STDOUT_SHOW_STDERR` (stdout captured, stderr left on ours, as a shell's `$(cmd)`), `on_line` (each line of the captured stdout as soon as the command writes it, for a caller that passes lines on live; with `output` merge, stdout or stdout-show-stderr, and timeout(1) in argv instead of `timeout`). `output` takes an `OutputMode` member and `fault` is a `CommandFault` member (`missing`, `unstartable`, `timeout`; both StrEnums in `cst_core.ports`); `stdin` is `"devnull"` (the default) or `"inherit"` (`StdinMode`). `c_locale(env)` gives an environment with `LC_ALL=C` for a command run outside the runner; `on_host_argv(argv, settings)` the `flatpak-spawn --host` command line of one, for a command a program execs or hands on itself (toolchains runs itself on the host with it, cpu-setup its `cpu-watch`). A command that is missing, cannot start or times out comes back with `fault` and `cause` set: a module keeps its own message from them (a 2-line binding), never its own `subprocess.run`; `r.raise_cause()` (`CommandResult`) gives `r` back or raises that cause, for a caller that lets it propagate as `subprocess.run` raised it (bulk and docker-volumes-nocow; docker-gc, vm, cpu, toolchains, bluetooth and snapshot still write its two lines out). Outside it on purpose: the children a program reads or watches while they run (`subprocess.Popen`: docker events, restic, `pactl subscribe`, the cpu watch, the stall monitor's alert, bulk's copy; each counted in `PRIMITIVE_BUDGETS`) and the dispatcher's foreground run. Not moved yet, counted in `PRIMITIVE_BUDGETS` (`tests/test_architecture.py`), never above their entry: stall-report and the restorecon call in `cst_core.adapters.files`. With `on_host` inside a container, `env` values go on `flatpak-spawn`'s command line: never a secret there. |

Root commands refuse inside a toolbox ([docs/architecture.md](../../docs/architecture.md#toolbox-vs-host)). |
| rpm-ostree's deployments | `cst_core.domain.ostree.query_status` (`OstreeStatus`: every deployment, the booted one, the next boot's) | Takes a run function (`argv -> (rc, stdout, stderr)`); doctor passes its `Host.run`. vm's `booted_deployment` passes its `run` (and records None for any failure); `btrfs-health-check` (`next_root` in `btrfs/health_check/adapters.py`) passes its probe's. The bash copies in the btrfs scripts stay until they are Python. |
| systemd | `SystemdPort` (`cst_core.ports`), `SystemctlAdapter` (`cst_core.adapters`) | start, stop, restart, enable/disable (`now=`), clean (`what=`), show (properties as a dict, `{}` when systemctl cannot answer; on the host from a toolbox unless `on_host=False`; C locale, 20 s unless the adapter has a timeout), daemon-reload (raises `CommandFailed`; `daemon_reload_result()` returns the result instead), is-active, is-enabled, show-environment, `show_value(unit, prop)` (`show -p PROP --value`, the adapter's timeout and locale). The adapter's `timeout` and `locale_c` apply to the other systemctl calls (off by default); its scope, off by default: `user` (`systemctl --user`), `program` (a stub instead of systemctl, never on the host), `on_host` (every call but `show`), `base_env` and `stdin` (every call). These new calls are on the adapter, not on `SystemdPort`; toolchains reaches the user manager with the scope; a caller with its own words for a missing systemctl gives them to the runner (`SubprocessCommandRunner(words=...)`). |
| libvirt | `VirshPort` (`cst_core.ports`), `SubprocessVirshAdapter` (`cst_core.adapters.virsh`) | virsh in the C locale through a `CommandRunnerPort`: `on_host`, `read_only` (`-r`); output that is not UTF-8 becomes U+FFFD. cpu and vm use it directly, doctor over its host's runner (`Host.virsh`). |
| Write a file | `cst_core.adapters.files.write_atomic` | Unique temp file, exact mode (or `mode="umask"`: what `open(path, "w")` gives a new file), fsync of the file and its folder (`durable="file"`: the file only; `durable=False`: none), owner `FileOwner.CALLER` or `FileOwner.ROOT` (`cst_core.adapters.files.FileOwner`), restorecon as root unless `relabel=False`. ## The gates that catch a copy

- `tests/test_duplication.py`: clones, and the same name defined in several
  files (Python top-level names and shell functions).
- `tests/test_architecture.py`: no I/O in `domain` or `application`; and
  `PRIMITIVE_OWNERS` / `PRIMITIVE_LITERALS`, which name the owner of each
  primitive (running a command, replacing or syncing a file, temporary files,
  locks, the NOCOW ioctl, parsing JSON or TOML: `json.load(s)` and
  `tomllib.load(s)` have no budget, so a call in production code outside
  `cst_core.domain.shapes` fails) and of the literals that betray a copy of one
  (`/run/.containerenv`, `/.dockerenv`, `flatpak-spawn`, `qemu:///system`,
  `LC_ALL`, `restorecon`, `systemd-escape`). A call or a literal anywhere
  else counts against its package's budget (`PRIMITIVE_BUDGETS`,
  `LITERAL_BUDGETS`), which it may not go above: a new copy fails. Every public
  name of cst_core's shared layers must have a user outside its file
  (`CORE_NAMES_WITHOUT_USER` lists today's exceptions).
- `tests/test_magic_values.py`: a word of a cst_core StrEnum (`OwnedState`,
  `Urgency`, ...) compared as a plain string, and a unit number written out
  (3600, 86400, 604800, 124, 126, 127, 137) where cst_core has its name
  ([magic-values](magic-values.md)).

See [docs/architecture.md, "Static gates beyond lint and types"](../../docs/architecture.md#static-gates-beyond-lint-and-types).
