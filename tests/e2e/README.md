# Docker E2E tests

These tests start Fedora 45 containers with systemd as PID 1 and run `cst` in
them. They need Docker. Run them through invowk from the repository root, or
call `tests/e2e/run.py` directly.

| Tier | Command | Privileged? |
|------|---------|-------------|
| 1 | `invowk cmd test e2e tier1` | No (`--cap-add SYS_ADMIN` only) |
| 2 | `invowk cmd test e2e tier2 --allow_privileged` | **Yes** (`--privileged`) |

Tier 1 (`suites/suite_tier1_systemd.py`):

- `test_01`: install and apply commands refuse inside a container.
- `test_02`: systemd PID 1, the system D-Bus and the user manager run.
- `test_03`: the `cst` dispatch, the `~/.local/bin/cst` link, `cst status` and `cst doctor`.
- `test_04`: toolchains: the timer, its settings and the prune. `auto off` refuses, with nothing removed and the timer still running, when `systemctl --user` cannot reach the user manager. A normal `auto off` stops the timer. A second `auto off` stops a timer an earlier one left running with its files gone (which `status` shows), and removes its dangling `timers.target.wants` link. The prune service logs under its own journal name (`journalctl -t cst-toolchains`).
- `test_05`: bluetooth `plan`, `apply --no-restart`, the WirePlumber roles checked by the real libwireplumber, the LDAC unit, and `revert`.
- `test_06`: the `btrfs-notify` queue delivered by `cst-pending-alerts` and seen by `cst doctor`, and real restic over SFTP to a NAS container.

- `test_08`: the real game profile `on`/`tick`/`off` against the real user manager: a slice of its own and a `systemd-run` job made idle, kept across the slice coming back, nothing added by a second `tick`, all reverted by `off` even for a slice already gone, a `zz-cst-game.conf` left behind removed by a `tick`. `cst doctor` flags the escaped slice, the job and the leftover drop-in, and not a `user-<x>.slice`.

Both commands take `--keep_logs` (keep the systemd, full boot journal and
docker logs in `tests/e2e/.artifacts/` even on success; CI and nightly upload
them from there with `include-hidden-files: true`) and `--rebuild` (rebuild
the images).
Without `--rebuild`, `run.py` uses a local image only when its label
`org.cst.e2e.sources` is the digest of this checkout's sources
(`tests/e2e/image_digest.py`: the image's Dockerfile, every file under
`tests/e2e/scripts` with its exec bit, and for `priv` the digest of
`systemd`, its base); an image with no label or another one is rebuilt with
the label, never used. `.github/workflows/e2e-images.yml` writes the same
label on the cache images it publishes, and the runner's hydrate step
(`.github/actions/prep-e2e-runner`) says when a pulled image's label is not
the checkout's (`run.py` then rebuilds it). The Fedora base image is not part
of the digest: the weekly images run and `--rebuild` pick up its updates.
The containers read and run the checkout from a bind mount. Where SELinux is
on, a checkout or git worktree labelled for a home folder (`user_home_t`)
would give "Permission denied" inside them, so `run.py` starts them with
`--security-opt label=disable` whenever it sees SELinux: at
`/sys/fs/selinux` on the host, or at `/run/host/sys/fs/selinux` inside a
toolbox (whose `docker` talks to the host's daemon). If SELinux is enforcing
and that option is not added, the run stops before any container starts and
prints the fix, `chcon -R -t container_file_t <checkout>`.

## Mixed-version tests

The history of this repository was rewritten on 2026-11-18. The commit SHAs in fixture names (`tests/fixtures/legacy/<file>@<sha>`) and the `(#NN)` pull request numbers in older commit subjects refer to the history before that date; the fixtures' contents are what the names describe.

A test that runs a previous version of a program next to this checkout's (an
upgrade over what an older CST installed, two copies sharing state files or a
lock) takes that version from `tests/fixtures/legacy/<file>@<short-sha>`: the
file copied byte for byte from the commit named after the `@` (the last one
before the change), never edited. Tests never read the git history (`git
archive`, `git show`): CI checks out one commit, and a source tarball has no
history at all. The test installs the fixture as the previous version (a copy
of the checkout with the fixtures put back in their places, or the program run
straight from the fixture). The fixtures carry no license line of their own
(`LICENSE_EXEMPT` in `tests/license_headers.py`: captured data); the shell ones
are in `SHELL_TEST_SCRIPTS` (`tests/shell_files.py`). Delete a fixture with
the last test that uses it.

## Tier 2 needs an explicit opt-in

Tier 2 runs a `--privileged` Docker container. Such a container sees all of
the host's block devices (`/dev/sd*`, `/dev/nvme*`, `/dev/loop*`), creates loop
devices and btrfs filesystems, and could change the host's real disks if a test
or `cst` itself goes wrong. CI runs it on throwaway GitHub runners.

So `run.py` refuses tier 2 (exit code 2, with an explanation) unless you opt in
with one of:

- the environment variable `CST_E2E_ALLOW_PRIVILEGED=1` (only the value `1` counts);
- `run.py --allow-privileged`;
- `invowk cmd test e2e tier2 --allow_privileged` or `invowk cmd test all --allow_privileged`.

`invowk cmd test all` checks the opt-in first, before the long unit and lint
runs. The CI and nightly workflows set `CST_E2E_ALLOW_PRIVILEGED=1` on their
tier 2 steps. Do not opt in on a workstation whose disks you care about: use
a disposable VM instead. Tier 1 needs no opt-in.

The unit tests for this guard are in `tests/e2e/test_run_guard.py`; they never
start Docker.
